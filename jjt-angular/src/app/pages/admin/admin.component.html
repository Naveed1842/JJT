How the System Works

Follow these steps in order for every child. Each step unlocks the next.

1
Add Child
Register the child with roll number, city, campus. The system creates an empty ledger automatically.
Tab → Add Child
›
2
Early Support
For each month JJT paid before a sponsor was matched, add one entry. This builds the child's ledger history.
Tab → Early Support
›
3
Add Sponsor
Create the sponsor record. Copy the Sponsor ID shown after saving — you need it for Steps 5 and 6.
Tab → Add Sponsor
›
4
Commit Sponsorship
Link sponsor to child with a future start month. Status is PENDING — child shows as "Bridged" publicly.
Tab → Commit Sponsorship
›
5
Activate
Once payment is confirmed, click Activate. Status becomes ACTIVE — child shows as "Sponsored" publicly.
Tab → Pending → Activate
›
6
Add Progress
Each month, write a progress update for the child. Month must match an existing ledger entry.
Tab → Add Progress
6b
Create Sponsor Login (optional)
If the sponsor wants portal access, go to Users → + Sponsor User. Paste the Sponsor ID from Step 3. Use the same ID — creating a new one will result in the portal showing no children.

Child Status Reference

SEEKING
No sponsorship exists. Child appears on the public browse page as available.
BRIDGED
A PENDING sponsorship exists. Commitment recorded but payment not yet confirmed.
SPONSORED
An ACTIVE sponsorship exists. Payment confirmed. Sponsor can see this child in their portal.

Key Rules

→ Progress updates require a matching ledger entry for the same month. Add Early Support first, then progress.
→ Commit Sponsorship start month must always be a future month. The system enforces this automatically.
→ When creating a Sponsor Login, always use the Sponsor ID from Step 3. A different ID creates a new empty sponsor — the portal will show no children.
→ The ledger is append-only — entries can never be deleted or edited. Each month gets exactly one entry.
